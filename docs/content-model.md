# مدل محتوای فاز ۱

## هدف

مدل محتوا مرز میان دادهٔ منبع و رابط کاربری را مشخص می‌کند. هر رکورد مستقل از صفحه، با شناسهٔ پایدار، منشأ قابل ممیزی و روابط صریح ذخیره می‌شود. نسخه‌های فارسی و انگلیسی مجموعهٔ شناسه‌های یکسان دارند؛ بنابراین تغییر زبان، مسیر و رابطهٔ کاربر را حفظ می‌کند.

## خروجی‌های مرجع

- `data/content.fa.json`: سند تجمیعی فارسی و مرجع کامل متن استخراج‌شده.
- `data/content.en.json`: سند تجمیعی انگلیسی با همان شناسه‌ها و وضعیت ترجمه.
- `content/{fa,en}/canvas.json`: گرهٔ ریشه، بخش‌ها و ۹ بلوک بوم.
- `content/{fa,en}/blocks/*.json`: بستهٔ هر بلوک برای بارگذاری تنبل.
- `content/{fa,en}/data-items/*.json`: رکورد مستقل پرسونا، رابطه، محرک ارزش و اسلاید.
- `content/{fa,en}/filters.json`: واژگان فیلتر و شمارش برچسب‌ها.
- `content/{fa,en}/index.json`: نمای سبک برای جست‌وجو و مسیریابی.
- `content/review-queue.json`: صف مواردی که نیازمند تصمیم یا بازبینی انسانی‌اند.

## ساختار رکورد

| فیلد | معنا |
|---|---|
| `id` | شناسهٔ یکتا و ثابت میان زبان‌ها |
| `slug` | کلید مسیر پایدار و انگلیسی |
| `type` | نوع محتوایی، مانند `canvas-block`، `persona` یا `source` |
| `status` | `available`، `partial`، `planned` یا `not_provided` |
| `title/summary/body` | محتوای محلی‌شده؛ بدنه در صورت نبود ترجمه حذف می‌شود، نه اینکه جعل شود |
| `parentId` | جایگاه در سلسله‌مراتب |
| `relatedIds` | روابط صریح با گره‌های دیگر |
| `personaIds` | اتصال محتوا به پرسوناها |
| `filterTags` | برچسب‌های قابل استفاده در فیلتر و جست‌وجو |
| `source` | نام فایل، شمارهٔ اسلایدها و شناسهٔ shapeهای PPTX |
| `visualization` | متادیتای بازسازی نمودار/جدول/لیست |
| `translationStatus` | وضعیت واقعی ترجمه، از جمله `title_only` و `working_terminology` |

قرارداد رسمی JSON در `schemas/content.schema.json` و قرارداد اجرایی Zod در `src/content/schema.ts` قرار دارد.

## رده‌بندی و شمارش فعلی

هر زبان ۱۸۰ گره دارد:

- ۱ گرهٔ ریشه
- ۸ بخش محتوایی
- ۹ بلوک بوم کسب‌وکار
- ۶ پرسونا
- ۴ محرک ارزش
- ۷ الگوی ارتباط با مشتری
- ۱۴۵ رکورد اسلاید برای پوشش بدون حذف منبع

## قواعد هویتی و رابطه‌ای

- شناسه و slug پس از انتشار تغییر نمی‌کنند.
- مجموعهٔ شناسه‌ها در فارسی و انگلیسی باید دقیقاً برابر باشد.
- `parentId`، `relatedIds` و `personaIds` تنها می‌توانند به شناسه‌های موجود اشاره کنند.
- هر شمارهٔ اسلاید ۱ تا ۱۴۵ باید دست‌کم در یک رکورد منبع حاضر باشد.
- مسیر مطلق فایل سیستم وارد payload عمومی نمی‌شود.

## وضعیت ترجمه

نسخهٔ انگلیسی از نظر ساختار، عنوان‌های ناوبری، شناسه و رابطه کامل است. ۲۵ گره ترجمهٔ کامل یا متن انگلیسی منبع دارند. ۱۵۵ گره برای ترجمهٔ بدنه یا تثبیت اصطلاحات در صف بازبینی‌اند. تا زمان تأیید، متن فارسی داخل فیلد انگلیسی کپی نمی‌شود و UI می‌تواند بر اساس `translationStatus` پیام مناسب نمایش دهد.

## لایهٔ دسترسی

`src/content/repository.ts` رابط `ContentRepository` و پیاده‌سازی `JsonContentRepository` را فراهم می‌کند. رابط کاربری از این abstraction برای واکشی فرزندها، روابط، نوع محتوا و جست‌وجو استفاده خواهد کرد؛ بنابراین مهاجرت آینده از JSON به headless CMS نیازمند تغییر کامپوننت‌های نمایشی نیست.
